# 7. אבטחה, הרשאות ופרטיות

## 7.1 תפקידים (Roles) ותחום (Scope)

ההרשאה = **תפקיד** × **תחום** (פלטפורמה / Tenant / מבנה / דירה) × **זמן** (אופציונלי).

| תפקיד | תחום טיפוסי | עיקר ההרשאות |
|-------|-------------|---------------|
| Platform Admin | פלטפורמה | ניהול Tenants, חבילות, תמיכה (גישה לנתוני לקוח רק ב-"Break-glass" מתועד) |
| Management Admin | Tenant | הכול בכל מבני החברה, מיתוג, הגדרות, משתמשים |
| Property Manager | מבנים משויכים | תקלות, ספקים, תחזוקה, כספים של המבנה |
| Technician / אב בית | מבנים משויכים | הזמנות עבודה, סיורים, פתיחת תקלות |
| Committee Chair | מבנה | הכול במבנה, כולל הגדרות ואישורים |
| Committee Member | מבנה | צפייה מלאה, ניהול תקלות, הודעות; כספים לפי הגדרה |
| Treasurer (גזבר) | מבנה | ניהול כספים |
| Resident / Owner | דירה | התקלות שלו, תשלומים שלו, מסמכים גלויים, הודעות |
| Company Rep (משרדים) | יחידה/ות | כמו דייר + ניהול עובדי החברה |
| Employee (משרדים) | יחידה | פתיחת תקלות, הזמנת חדרים |
| Vendor Admin / Vendor Tech | הזמנות שהוקצו + AccessGrant | צפייה בתקלות שהוקצו בלבד, עדכון ביצוע |
| Auditor | AccessGrant למבנים, מוגבל בזמן | ביצוע ביקורות, צפייה במסמכי ציות ובאישורים |
| Stats Consumer | API / דשבורד סטטיסטי | נתונים מצטברים ואנונימיים בלבד |

**מימוש:** RBAC + ABAC (בדיקת Scope ו-Ownership) בשכבת השירות, **ובנוסף** RLS ב-PostgreSQL כשכבת הגנה שנייה מפני דליפה בין Tenants.

## 7.2 אימות (Authentication)

- OTP ב-SMS/מייל כברירת מחדל לדיירים (ללא סיסמה).
- סיסמה + 2FA (TOTP / Passkeys) חובה לתפקידי ניהול, ועד, מבקר וספק.
- SSO (OIDC/SAML — Azure AD / Google Workspace) לחברות ניהול גדולות ולמגדלי משרדים.
- JWT קצר-טווח (15 דק') + Refresh Token מסובב, ביטול סשנים.
- הגנת Brute-force, Rate limiting, CAPTCHA בהתאם לסיכון.

## 7.3 הגנת מידע

- TLS 1.2+ בכל התעבורה, HSTS.
- הצפנה במנוחה (דיסקים, DB, Object Storage, גיבויים).
- הצפנה ברמת שדה לנתונים רגישים: ת"ז, פרטי חשבון בנק.
- **אין שמירת פרטי כרטיס אשראי** — טוקניזציה אצל חברת הסליקה (PCI-DSS SAQ-A).
- קבצים: URL חתום קצר-טווח, סריקת וירוסים בהעלאה, הגבלת סוגים וגדלים, הסרת EXIF/GPS מתמונות דיירים.
- Secrets ב-Vault / KMS, לא בקוד.
- Audit Log בלתי ניתן לשינוי (Append-only), כולל צפייה בפרטי קשר וייצואים.

## 7.4 פרטיות ורגולציה (ישראל)

- **חוק הגנת הפרטיות** (כולל תיקון 13) ו**תקנות אבטחת מידע (2017)**: רישום/הגדרת מאגר לפי הצורך, נוהל אבטחה, מינוי ממונה אבטחת מידע ו-DPO לפי הדרישה, סקר סיכונים ומבדק חדירה תקופתי.
- **מזעור מידע**: איסוף רק מה שנדרש; ת"ז רק אם נדרש לצורך משפטי.
- **הסכמות**: לקבלת הודעות שיווקיות (חוק הספאם), לחשיפת טלפון לשכנים, לשיתוף נתונים מצטברים.
- **זכויות נושא מידע**: עיון, תיקון, ייצוא ומחיקה (בכפוף לחובות שמירת מסמכים פיננסיים).
- **הפרדת תפקידים**: הוועד/חברת הניהול = "בעל המאגר"; הפלטפורמה = "מחזיק" — הסכם עיבוד נתונים (DPA) עם כל לקוח.
- **אנונימיזציה לסטטיסטיקה**: k-anonymity (k≥10 מבנים בכל תא), Differential Privacy (רעש מבוקר) בפילוחים קטנים, ללא גישה לרמת רשומה.
- **GDPR**: התאמה בסיסית לקראת לקוחות אירופאים בעתיד.

## 7.4.1 מערכות בקרה (OT)
מערכות בטיחות חיים בקריאה בלבד, תקשורת יוצאת בלבד, תעודה לכל Gateway, ואישור של שני אנשים לפקודות רגישות. עבודה לפי IEC 62443. הפירוט ב[מסמך 11](11-smart-building.md#118-אבטחת-סייבר-ot).

## 7.5 אבטחת פיתוח (Secure SDLC)

- סקירת קוד חובה, SAST (CodeQL/Semgrep), סריקת תלויות (Dependabot/Renovate), סריקת Images (Trivy).
- בדיקות אוטומטיות לבידוד Tenants (כל API נבדק שלא מחזיר נתונים של Tenant אחר).
- OWASP ASVS Level 2 כיעד.
- מבדק חדירה חיצוני לפני השקה ואחת לשנה.
